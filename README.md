A robust, self-contained Go backend and Vue.js frontend for managing and visualizing geospatial tree data.

This project provides a complete, production-ready solution for creating, managing, and importing tree location data, with an initial focus on Lausanne, Switzerland.

It is built as a single, self-contained Go binary that serves both a powerful JSON API and a fully-featured, embedded single-page application (SPA).

## Core Features

✨ **API-First Design**: The entire server is generated from an OpenAPI 3.0 specification using `oapi-codegen`. The contract is the single source of truth.

📦 **Self-Contained Binary**: Uses Go's `embed` feature to bundle the entire Vue.js frontend and all SQL database migrations directly into the server binary. Deployment is as simple as copying one file.

📐 **Clean Architecture**: Follows a clear three-layer architecture (Handler, Service, Storage) to separate concerns, making the application easy to maintain, test, and scale.

🧪 **Testable by Design**: Leverages dependency inversion by defining a `Storage` interface, allowing the database layer to be easily mocked for unit tests.

🚀 **Production Ready**: Includes production necessities like:

* Structured, leveled logging.
* Graceful server shutdown.
* `/health` and `/readiness` endpoints for container orchestration (e.g., Kubernetes).

🔐 **Secure by Default**: API endpoints are secured using JWT (JSON Web Tokens), with auth logic handled cleanly in the service layer.

🗄️ **Database Migrations**: Uses `golang-migrate` to manage database schema evolution, with migration files embedded in the binary for foolproof deployments.

## Project Architecture

This project follows the [Standard Go Project Layout](https://github.com/golang-standards/project-layout).

* `/cmd/geoTreeTableServer`: Main application entrypoint, responsible for initialization (config, logger, DB), dependency injection, and server startup.
* `/pkg/geoTree`: The core business logic, split into:
    * `service.go`: The HTTP handler layer (Echo).
    * `storage.go`: The `Storage` interface (dependency inversion).
    * `storage_postgres.go`: The concrete PostgreSQL implementation.
    * `auth.go`: Authorization logic.
    * `*.gen.go`: Types and server interfaces generated by `oapi-codegen`.
* `/api`: The OpenAPI `geoTree.yaml` contract.
* `/cmd/geoTreeTableServer/db/migrations`: SQL migration files.
* `/cmd/geoTreeTableServer/geoTreeTableFront`: The complete Vue.js frontend source code.

## Getting Started from source

Follow these instructions to get the backend server running locally for development.

### 1\. Prerequisites

* **Go** (v1.21 or later)
* **PostgreSQL**: A running instance (e.g., via Docker or a local install)
* **Make**: (Optional, but recommended for building)
* **Wget & Jq**: (Required by some scripts, e.g., `getAppInfo.sh`)

### 2\. Clone the Repository

```bash
git clone https://github.com/lao-tseu-is-alive/go-geo-tree-table.git
cd go-geo-tree-table
```

### 3\. Set Up the Database

A helper script is provided to create the local database and user. It will prompt for the `postgres` admin password.

```bash
# Make the script executable
chmod +x ./scripts/createLocalDBAndUser.sh

# Run the script
./scripts/createLocalDBAndUser.sh
```

This will create the `geo_tree_table` database and the `geo_tree_table` user, matching the defaults in the environment config.

### 4\. Configure Your Environment

The application is configured using environment variables. A sample file is provided.

1.  Copy the sample to a new `.env` file (which is git-ignored):

    ```bash
    cp .env_sample .env
    ```

2.  **Edit the `.env` file:**

    * Update `DB_PASSWORD` to the password you set up.
    * Change `JWT_SECRET` to a long, random, and private string.
    * Update `ADMIN_PASSWORD` to a secure password.
    * Review all other `changeme_` values.

### 5\. Run the Application

You can run the application in two ways:

#### Option A: Run in Development (with Hot-Reload)

The `GoRunWithEnv.sh` script sources your `.env` file and runs the app using `go run`, which recompiles on changes.

```bash
# Make the script executable
chmod +x ./scripts/GoRunWithEnv.sh

# Run the server
./scripts/GoRunWithEnv.sh
```

The server will start (by default on `http://localhost:7979`) and run the database migrations automatically.

#### Option B: Build and Run the Binary

1.  **Build:** Use `make` or standard Go commands to build the self-contained binary.

    ```bash
    make build
    ```

    This creates a binary named `go-geo-tree-table` in the root.

2.  **Run:** Use the `execWithEnv.sh` script to run the compiled binary, loading your `.env` file first.

    ```bash
    # Make the script executable
    chmod +x ./scripts/execWithEnv.sh

    # Run the compiled binary
    ./scripts/execWithEnv.sh
    ```

## Kubernetes Deployment

This project is designed to be deployed on Kubernetes. The manifest files in the `/deployments/go-testing` directory provide a robust, GitOps-friendly foundation.

### Core Concepts

The application's configuration is separated into three K8s resources, which are mounted into the running container as environment variables:

1.  **`configmap-go-geo-tree-table.yaml`**: A `ConfigMap` that holds all **non-sensitive** configuration (e.g., port numbers, service names).
2.  **`app-secrets-go-geo-tree-table.yaml`**: A `Secret` that holds all **sensitive** configuration (e.g., database passwords, JWT secrets).
    * A safe, commented template is provided in `app-secrets-go-geo-tree-table.sample.yaml`.
3.  **`deployment.yml`**: The K8s `Deployment` that runs the application. It uses `configMapKeyRef` and `secretKeyRef` to inject configuration from the resources above.

### Sealed Secrets (GitOps Workflow)

This repository is configured for **Sealed Secrets** (from Bitnami). This allows you to store your application secrets in Git in an encrypted ("sealed") form, which is safe to commit. A controller in the cluster is the only thing that can decrypt them.

The `sealed-app-secrets-go-geo-tree-table.yaml` file is the encrypted, safe-to-commit version of your `app-secrets-go-geo-tree-table.yaml`.

### Deployment Workflow

Here is the one-time setup and repeatable deployment process:

#### One-Time Setup

1.  **Install Sealed Secrets:** You must have the [Sealed Secrets controller](https://github.com/bitnami-labs/sealed-secrets) installed in your cluster.
2.  **Install `kubeseal` CLI:** You need the `kubeseal` command-line tool locally to encrypt your secrets.

#### Deployment Steps

1.  **Prepare Secrets:**

    * Copy the `app-secrets-go-geo-tree-table.sample.yaml` file to a new file named `app-secrets-go-geo-tree-table.yaml` (this file is git-ignored and should **never** be committed).
    * Edit `app-secrets-go-geo-tree-table.yaml` and fill in all your production/staging values.

2.  **Encrypt (Seal) Your Secrets:**

    * Run the `kubeseal` command to encrypt your secret file. The `createAppSecrets.sh` script is a reference for this process.
    * **Note:** You must target the namespace and controller name of your cluster.

    <!-- end list -->

    ```
    # Example kubeseal command
    # Adjust namespace and controller name as needed
    kubeseal < app-secrets-go-geo-tree-table.yaml \
      --controller-name sealed-secrets \
      --controller-namespace kube-system \
      -o yaml \
      > sealed-app-secrets-go-geo-tree-table.yaml
    ```

    * This overwrites the existing `sealed-app-secrets...yaml` file with your new, encrypted secrets. You can now safely commit this file.

3.  **Apply Manifests to Cluster:**

    * Apply the configuration and deployment to your cluster.

    <!-- end list -->

    ```
    # 1. Apply the non-sensitive configuration
    kubectl apply -f deployments/go-testing/configmap-go-geo-tree-table.yaml

    # 2. Apply the encrypted secrets
    # The Sealed Secrets controller will see this and create the real Secret
    kubectl apply -f deployments/go-testing/sealed-app-secrets-go-geo-tree-table.yaml

    # 3. Apply the application deployment
    # This will pull the new image and start, using the config and secrets
    kubectl apply -f deployments/go-testing/deployment.yml
    ```
